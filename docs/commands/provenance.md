# provenance

`greengate provenance` classifies non-merge commits using recognized tool names in author identity, supported trailers, and selected generated-with markers. It reports commit counts and added-line counts by classification and can gate the estimated AI share.

```bash
greengate provenance --base origin/main
greengate provenance --base origin/main --format json
greengate provenance --base origin/main --max-ai-lines-pct 50
```

| Flag | Default | Purpose |
|---|---|---|
| `--base` | `main` | Analyze commits in `base..HEAD` |
| `--max-ai-lines-pct` | unset | Fail if the rounded estimated AI share of added lines exceeds this percentage |
| `--format` | `text` | Print text, JSON, or SARIF |

Supported signals include `Co-Authored-By` and `Assisted-By` values mentioning recognized tools. A matching commit's added lines are attributed to that classification; the command does not attribute individual lines from their contents.

This is metadata-based estimation, not verified authorship or software-build provenance. Missing trailers, changed author identities, unmarked AI assistance, merge commits, and repeated line additions can affect the result. It does not prove whether code was generated by a model or reviewed by a person.

Without a ceiling, the command reports rather than blocks. A ceiling violation exits `1`; Git or other runtime failures exit `4`. See [exit codes](/reference/exit-codes).
